H+c 4FS FxFx → WW: rebuilt and validated gridpack
for a Run 3 re-production

Gridpack, fragment and validation for the HToWW contacts / GEN

Chirayu Gupta · 2026-11-04 · revision r2

Internal. Private-production plots ("Simulation Private work"); not CMS-approved and not for public use. The 3FS gridpack is in a separate deck.

Summary

  • The central Run 3 H+c → WW (4FS FxFx) samples have wrong scale/PDF weights (gridpack build) and a misconfigured FxFx merging (fragment).
  • We rebuilt the gridpack on el8 from the unchanged official cards, with build scripts that keep MG5_aMC's internal reweighting, and completed the fragment with the three missing FxFx lines.
  • Validated at LHE+GEN level against the official clean 4FS H→γγ gridpack, same H→WW fragment, ≈ 10k events each:
    • PDF replicas / member 0 = 0.999 (broken central samples: 2.26)
    • all 9 scale variations within 0.7% of official
    • σ = 155.5 ± 0.4 fb (identical), all kinematic shapes χ²/ndf ≤ 1

Ask: re-produce the 4FS (and H+b) H→WW requests with the rebuilt gridpack and fixed fragment.

Why: two problems in the central H+c/H+b → WW samples

1. LHE scale/PDF weights wrong (gridpack build)

  • all scale variations ≈ ×2 nominal, PDF replicas / member 0 ≈ 2.26
  • cause: the genproductions NLO workflow switches off MG5_aMC's internal reweighting and computes the weights with the python systematics module, which ignores the running charm Yukawa added by the cards' _mg5amc.patch

2. FxFx merging misconfigured (fragment)

  • the WW requests lack JetMatching:jetAlgorithm = 2, etaJetMax = 999., coneRadius = 1. → veto only at |η|<2.5, R = 0.7
  • forward 1-jet events 7× rarer; not fixable by reweighting

What was fixed in the gridpack build

  • Physics cards (proc, run, param, extramodels, _mg5amc.patch) are the official CMS cards, unchanged and identical to those of the official clean H→γγ 4FS gridpack. The bug is purely in the build scripts.
  • The running-Yukawa patch comes from the official cards on GitHub (cms-sw/genproductions, 13p6TeV/HPlusHF):
    github.com/cms-sw/genproductions/…/HPlusHF/HPlusCharm_4FS_…_amcatnloFXFX_pythia8_mg5amc.patch
  • Build-script change (only for cards that carry this patch): keep MG5_aMC's internal reweighting and skip the python systematics step. This is what the official clean gridpacks do; every other process builds as before.
  • Built on el8 with CMSSW_12_4_8, MG5_aMC 2.9.18. Integrated σ = 155.5 ± 0.4 fb, identical to the official gridpack.
  • Fragment: the official H→WW fragment plus the three missing FxFx lines (backup).
The validation on the next slides was run on exactly the gridpack in the package.

  • Build history: two packaging slips in early builds (missing MetaData/; runcmsgrid.sh not executable) were caught by the tests and fixed before the validation shown here.

  • Running-Yukawa patch: the _mg5amc.patch in the gridpack is identical to the GitHub cms-sw/genproductions card (13p6TeV/HPlusHF).
