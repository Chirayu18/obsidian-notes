# Central H+c / H+b → WW signal samples: broken LHE weights and FxFx merging

Write-up of the issue found 2026-10-13. The full investigation log is in [[2026-10-01-full-rerun-plan-and-findings]] (2026-10-13 sections). The GEN ticket draft is [[2026-10-13-GEN-ticket-draft-HplusC-HplusB-WW]]. Framework action items are in [[2026-10-08-framework-optimization-plan]] (P0-15, P0-16, P1-9).

## TL;DR

The central Run 3 H+c→WW and H+b→WW 4FS/5FS FxFx samples have two independent production problems.

1. **The LHE scale and PDF weights miss the running-Yukawa factor.** Fixable in the analysis with a per-event correction, which is implemented and validated for H+c.
2. **The FxFx merging is misconfigured** (fragment). The FxFx veto only acts at |η| < 2.5, with R = 0.7. This is not fixable by reweighting, but its effect inside the analysis selection (≥1 c-jet, |η| < 2.4) is about 1–2%.

**Decision for the current analysis:** use the existing samples with the per-event correction. Ask GEN for a re-production with both fixes for future iterations.

## Problem 1: LHE weights

- **Symptom:**
  - All scale variations are about ×2 the nominal (both directions up).
  - The per-event mean of the PDF replicas over member 0 is ≈ 2.26, instead of 1.
  - The nominal and member 0 are correct (σ 0.298 pb at 13.6 TeV vs 0.264 pb for Run 2 at 13 TeV).
- **Cause:**
  - The HPlusHF cards carry `_mg5amc.patch`, which puts the MS-bar running Yukawa into MG5_aMC's Fortran reweighting (`rwgt_muR_dep_fac`; m̄_c(3 GeV) = 0.986, nf = 4; m̄_b(m_b) = 4.18, nf = 5).
  - The current `genproductions_scripts` master NLO workflow appends `reweight_scale/PDF = False` and `store_rwgt_info = True` to the run_card, and computes the weights with the python `systematics` module. That module never applies the factor.
  - The official H+c→γγ gridpacks avoid this through a manual `runcmsgrid` change (skipping systematics) that lives only inside their tarballs.
  - The gridpacks were built following the official instructions (master + the same cards), so this is a workflow/documentation gap, not a user error.
- **Correction (implemented):** `analysis/corrections/lhe_yukawa_fix.py`, tables in `analysis/data/lhe_yukawa/` (generated by `tab.f` / `build.sh` from the patch's own runalpha/runmass, MG 2.9.10 source).
  - r = mean(PDF 1–100) / member 0 = 1/F(μ0) per event. Invert to μ0, then multiply each scale weight by F(k·μ0; μ0).
  - The tables start at **1 GeV, MG's renormalisation-scale floor**. About 0.8% of one-jet H-events sit exactly there, with constant ratios 6.199 / 0.308 in clean samples; these are reproduced exactly.
  - Events with F(μ0) > F(1 GeV) (near-total cancellations, ~1e-4) get no variation.
  - Clean samples are refused (median r < 1.2).
  - PDF: the per-event replica-mean centring in `lhepdf.py` is already exact.
- **Validation (H+c only):**
  - Single-scale events reproduce the patch to < 0.1%.
  - A two-piece (real vs counterterm scale) un-mixing changes results by ~1%.
  - The edge-case audit is clean (`runall/edge_audit.py`).
  - In the analysis-like region, the scale shapes agree with the clean γγ and Run 2 samples to ~1–2%. The acceptance per variation agrees to ~1 point (muR-down ~1 pt high, i.e. conservative).

## Problem 2: FxFx merging (fragment)

- **Symptom:** inclusively, one-jet events with the leading parton at |η| > 2.5 are 7× rarer (0.98% vs 6.6–6.8%), and zero-jet events with a hard forward parton (pT > 30 GeV) are 10× more frequent (1.9% vs 0.2%). This changes the 0/1-jet mix (80% vs 73% 0-jet) and the inclusive scale-variation shapes by 1–5%.
- **Cause:**
  - All seven WW GEN requests lack `JetMatching:jetAlgorithm = 2`, `JetMatching:etaJetMax = 999.` and `JetMatching:coneRadius = 1.`. These are HIG-Run3Summer22EEwmLHEGS-02600 / -02645, HIG-Run3Summer22wmLHEGS-02684 / -02697, HIG-Run3Summer23BPixwmLHEGS-02468 / -02517 and HIG-Run3Summer23wmLHEGS-03356.
  - FxFx forces kT anyway, but `etaJetMax` and `coneRadius` are used, and their Pythia defaults are 2.5 and 0.7.
  - The γγ, DY+jets FxFx and ggH FxFx fragments of the same campaign, the Run 2 UL18 WW sample and CMSSW's standard FxFx config all have the three lines.
- **Effect inside the analysis selection** (≥1 gen c-jet pT > 20, |η| < 2.4):
  - Nominal acceptance is 29.3% for ours vs 29.7% (γγ) and 28.5% (Run 2, 13 TeV).
  - Scale shapes are within the spread of the two clean references.
  - Forward-jet modelling is wrong, but the selection does not use forward jets.
