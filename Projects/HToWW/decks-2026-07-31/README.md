**Structure**

## The closure A/B — how it was built

Non-destructive. Nothing in `hww_combine_fixed` was modified.

| | no-SF variant | with-SF variant |
|---|---|---|
| workflow yaml | `hww_combine_nosf.yaml` (= `hww_combine_fixed.yaml` minus the `CMS_ctag2d_2022` line) | `hww_combine_sfchk.yaml` (verbatim copy) |
| tree | `outputs/hww_combine_nosf/2022postEE/` — **585 symlinks** to `.bak_pre_ctag2dsf` | `outputs/hww_combine_sfchk/2022postEE/` → symlink to the live tree |
| nuisance count | 29 | 30 |
| output | `v11_hplusc_nosf.{root,txt}` | `v11_hplusc_sfchk.{root,txt}` |

Both go through the *same* builder on the *same* day, so the only differences are the
central-SF weight rescale and the one nuisance row.

### ⚠️ Two configuration problems this uncovered

**1. `read_scale` was reading the wrong `sumw`.** There are three sources; the builder
hand-rolls its own sum instead of calling the repo's `read_parquet_sumw()`. It is now on the
**self-normalising `sumw_records`** (pre-selection, every read-chunk). The sidecar json turned
out to be *stale for the signal* — records = shard-metadata = 7.823e+04 vs sidecar 9.266e+04,
with the 80 records proven to tile all 80 files (0 gaps, 0 overlaps). Signal template +18.4%.

**2. LOWESS `smooth_shapes` was double-treating the negrw vjets templates.** Now `false` in
every workflow; the limit *improves* ~2% and stat-only is unchanged, as it must be.

Full write-up + both backup sets: [[2026-07-31-sumw-normalization-trap]].

**Sanity check for any future rebuild:** SR V+jets ≈ **735** (no SF) / **746** (with SF).
If V+jets is ~3780, the wrong `read_scale` is active.

### 2D-cat arm: re-measured 2026-07-31

The tree was not missing *data* — the **merge had been interrupted**. All raw shards were
present; only 34 of 57 group parquets had been written (it stopped alphabetically around "T").
Completed with the repo's own `merge_parquet_files` (`scripts/merge_2dcat.py`):

- **23 merged**, including `WtoLNu_2Jets` from **482 shards** → 57/57
- 10 "skips" are process-group *aliases* (`V+Jets`, `WH`, `ZH`, `ggH`, `WG`, `VBF`,
  `ttHnonBB`, …) that have no shards in *either* tree — correctly skipped
- verified the tree then had **all 35 samples the v11 build actually consumes**

Then re-ran one-hots → inference (285 files scored) → build (35 ok, 0 smoothing,
0 sumw fallbacks) → limit.

**Result, all three arms on the same configuration:**

| variant | full | stat-only | freeze-aMCS |
|---|---|---|---|
| baseline, no SF | **1150** | 668 | 905 |
| baseline + SF | **1164** | 676 | 930 |
| **2D-cat + SF** | **1676** | **637** | 1393 |

Stat-only **improves −5.8%** (637 vs 676) — the 2D-cat MVA is genuinely sharper. But the full
limit is **+44% worse**, where the old sidecar+smoothing series showed only +6%. The SR
composition explains it: signal ×1.29 but **tt ×2.33** (7,274 → 16,939), total ×2.25, so
$S/\sqrt{B}$ *falls* to 0.86×. Stat→full inflation 1.72× (baseline) vs **2.63×** (2D-cat).

<span>**On the current configuration, baseline scores + SF is the better choice.**</span>
