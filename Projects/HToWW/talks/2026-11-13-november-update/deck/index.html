Terms used in this talk

4FS / 3FSfour- or three-flavour scheme: the charm quark is massless and in the proton (4FS), or massive and produced only in the hard process (3FS)
Arm Asignal from the central 4FS FxFx H+c sample alone; a 3FS-vs-4FS shape uncertainty covers the scheme choice
Arm Bsignal stitched: 4FS for events with no GEN c-jet, private 3FS for events with ≥1 GEN c-jet
TRAIN / RUNtwo processing modes: TRAIN writes slim nominal features for MVA training; RUN scores events inline and writes histogram templates for all shifts
Foldevent % 5. Model i never sees fold i in training; RUN scores each event with the model that held it out, so all events enter the templates
b-hivethe training framework for the event MVA (6-class DNN)
negrwnegative-weight reweighting for amc@NLO V+jets: replaces signed weights by |w|·g(x), g = classifier estimate of the positive fraction
prompt MVAthe ttH lepton MVA used to select prompt leptons (Thomas's HWW working points)

Analysis recap: one eμ pair, one c-jet, a 6-class MVA

  • Selection: exactly one eμ pair, MET > 45 GeV, ≥1 c-jet candidate, triggers, MET filters, good vertex
  • Classes: H+c, Higgs background, tt, single top, diboson, V+jets
  • Channels: each event goes to the channel of its highest-score class: 1 SR + 5 CRs
  • New: the SR is split into Nc-jet = 1 and ≥ 2 (AN-23-102: +8% sensitivity in Run 2)

26 input features

  • 14 kinematic: pT(ℓℓ), pT(ℓ1,ℓ2), pT(c), MET, mT(ℓ1,ℓ2), mℓℓ, ΔR and Δφ between leptons, c-jet and MET
  • 11 one-hot c-tag categories (L0, C0–C4, B0–B4) from PNet CvsL × CvsB
  • nSV (secondary vertices)

The selection and features are unchanged in definition; the leptons and corrections feeding them changed.

H+c, H→WW · November analysis update · 13 Nov 2026 · internal CMS · preliminary · checks not independently reviewed

MVA reliability: a validation-duplication bug, fixed and tested

  • Found: b-hive's loader re-emitted the leftover partial batch, so validation and inference rows were duplicated
  • Size: on 129 real validation files, 103,980 rows emitted for 38,700 events (2.69×); inference 170,465 rows for 64,073 held-out events
  • Effect: biased the validation loss, hence best-epoch selection (and v11's)
  • Fix: every row emitted exactly once: tests over partial, exact-multiple and tiny files, with 0/2/3 loader workers
  • Training unchanged: epoch-0 weights bitwise identical before and after the fix
  • Reproducible: same seed on an A100 → bitwise-identical weights (max |Δw| = 0)
  • Provenance: each fold records code hashes; registration refuses pre-fix or mixed-code folds

Model selection now uses a clean validation sample, and a rerun gives the same model.

hDamp: the missing tt matching uncertainty

  • What: POWHEG's hdamp sets where hard real emission hands over to the shower. Varying it probes ME–PS matching for the top
  • Why here: tt is a main background with its own CR and enters the SR; hDamp changes jet multiplicity and the extra-jet spectrum, so c-jet and category migrations
  • Not covered by ISR/FSR: those vary shower radiation; hdamp varies the matching scale
  • Samples: dedicated TTto2L2Nu_Hdamp158 (Down) and _Hdamp418 (Up), configured in all 4 eras (σ = 98.578 pb)
  • Plan: alternative-sample templates, each normalised by its own Σw; compare to nominal tt in D, Njet, acceptance; check MC stat; one nuisance on tt
  • Status: deferred until after the MVA training; no template or card yet. Alternative samples stay out of the training sample

Adds the standard tt matching variation; results come with the RUN production.
