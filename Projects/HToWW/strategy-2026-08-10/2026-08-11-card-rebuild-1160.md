## What changed

### 1. PDF and alphaS: flat lnN → per-event shapes ⭐ the actual source of the gain

- `xsec_hplusc_PDF` **1.06 lnN** → **`lhe_pdf` shape**
- `alphaS_PDF` **1.03 lnN** → **`lhe_alphaS` shape**

The weights were already in the parquets (`weight_lhe_pdf{Up,Down}`,
`weight_lhe_alphaS{Up,Down}`) — `lhepdf.py` builds the full 100-replica NNPDF31 Hessian
envelope and we were collapsing it to a flat number **applied to hplusc only**. HiggsDNA
treats alphaS as a shape from `LHEPdfWeight[:,-1]/[:,-2]`; hh2bbww carries a `pdf` shape.

**Why this improved the limit:** freezing each new nuisance individually barely moves
anything (1156–1160), so none is expensive on its own. The gain came from *removing the flat
lnNs*, which were over-penalising — a blanket worst-case applied uniformly, versus a per-event
shape carrying the real correlation structure.

### 2. `BR_Htautau` 1% added

AN-23-102 Table 16 lists it next to BR(H→WW). We have `GluGluHto2Tau`, `VBFHToTauTau`,
`W±HTo2Tau`, `ttHtoTauTau` in `higgsbkg` and had no nuisance. Costs nothing (freezing it
leaves the limit at 1160) but closes a real gap.

### 3. `flavor_composition_ggH` kept at 1.066 (interim)

Restored after the split failed (below). Superseded once the reprocessing campaign produces
the per-event `higgs_plus_c` weight.

## ⚠️ The `higgsbkg` split FAILED — and would have been a silent, damaging bug

**Attempted, verified broken, reverted.** Do not retry as a config change.

`make_combine_inputs.py` derives the datacard processes from **`combine.classes`** — the 6
MVA output classes — at lines ~389–391:

```python
classes    = combine["classes"]
backgrounds = [c for c in classes if c != signal]
processes  = [signal] + backgrounds
```

`process_map` only maps a *class* to its constituent parquet `process` names. **A
`process_map` key with no matching class is silently ignored**, so adding `ggH: [ggH, ggZH]`
deleted those samples from the card entirely.

Verified damage before revert:

| | before | after split |
|---|---:|---:|
| SR total | 20664.132 | **20561.370** |
| SR `higgsbkg` | 131.092 | **28.330** |
| `flavor_composition_ggH` row | applied | **all dashes** |

~103 ggH/ggZH events vanished, and the uncertainty applied to nothing. **Neither error would
have raised** — the build exited 0.

**To do it properly:** either (a) add a 7th MVA class → **retraining**, or (b) decouple
datacard processes from argmax classes in `make_combine_inputs.py` so channel and process are
separate concepts. (b) is the real fix and needs sign-off.

**Or skip it:** the per-event `higgs_plus_c` weight sidesteps the whole problem — it keys on
gen-jet flavour, so grouping stops mattering.

A warning comment is now in the yaml above `process_map`.
