The module size has to be a run-time input

Variable module size in the kernel

Phase 1: constexpr layout · Phase 2: layout from the module size

Phase 1: every module is 160 × 416

  • bitmap layout is constexpr: 5 words per column, 2080 words
  • edge rule uses a fixed last row and column

Phase 2: size depends on the module

  • read from PixelTopology in beginRun
  • stored per morphing module as rows << 16 | cols
  • kernel derives the layout from it:

W = ⌈rows / 32⌉   mask = 2rows mod 32 − 1

W = words per column (21 for 672 rows, 43 for 1354); the mask drops the rows past the module in the last word

GPU basics: blocks, threads, shared memory

What one block of FindClus has to work with

  • Work division = number of blocks × threads per block
  • Blocks are independent; threads within a block share memory and wait at syncBlockThreads
  • Shared memory: on-chip, fast, per block. Run-3 and Phase-2 HLT budget: 48 KB
  • Registers: per thread, they cap the block size. T4: FindClus uses 143 registers → at most 384 threads
  • Alpaka independent_group_elements(acc, n): the block's threads stride over n items

Everything one block needs for one module must fit in 48 KB

Work division of FindClus: Phase 1 vs Phase 2

Phase 2 already ran one block per module in master; kept

Phase 1: 64 blocks, each loops over modules

fake pixels stored per block: 64 × 2400

Phase 2: 4000 blocks, one per module

per-block fakes: 4000 × 1000 slots · per morphing module: 216 × 1000 ≈ 4.5 MB, 18× less

Phase-1 morphing: a closing on a 1-bit bitmap

What runs in the Run-3 HLT since 2025 (#48734, #49991)

real pixels
4 clusters
1. dilate 3×3
candidates
2. erode, plus shape
recovered: 2 clusters

Toy computed with the kernel's rules: the track is joined, the pixel 3 columns away is not

  • image: 1 bit per pixel, 32 rows per word
  • dilate: temp = empty pixels with any of the 8 neighbours set
  • erode: keep a candidate if its 4 neighbours are all in image ∪ temp
  • recovered ("fake") pixels only link clusters; dropped before the output, no charge added
  • edge rule: beyond a row edge counts as filled, beyond a column edge as empty
  • two buffers (#49991): read one, write the other, no race

32 pixels per instruction: shifts, ORs and ANDs on whole words

Strips of 44 columns with a 2-column halo

5 strips for L1, 10 for 434-column modules

Load

real pixels of 48 columns into image, straight from the column histogram (contiguous)

Morph

dilate the 46 inner columns, erode and emit fakes for the 44 strip columns only; columns outside the module stay empty

Skip

strips with no pixel within ±1 column: one comparison of hist.off, same decision in all threads

Same answer as a whole-module bitmap, by construction (validation)

Why 44 columns, and why a halo of 2

The widest strip that fits the Phase-1 buffers

(S + 2·2) × 43 ≤ 2080

strip + halo  ×  ⌈1376 / 32⌉ words  ≤  Phase-1 buffer

S ≤ 44.4  ⇒  S = 44

48 × 43 = 2064 words ≤ 2080

  • 2080 = Phase-1 buffer (160/32 × 416)
  • 1376 = 1354 rows rounded up to a word
  • zero extra shared memory: the same two 8.3 KB arrays

Halo 2: erosion needs the dilation of the next column

  • halo 1 misses pixels at every strip edge
  • control: halo = 1 fails in 4 of 5 morphing modules of the unit test
  • the CPU SiPixelDigiMorphing has exactly this bug (validation)

Two limits the CPU backend could not see

Shared memory and registers, measured on a Tesla T4

Shared memory: 52 624 B > 48 KB

nvlink reserved the Phase-1 bitmaps in the Phase-2 kernel, despite if constexpr. Fix: one pair of buffers declared once, for both phases.

Registers: 448 threads > 384

Growing the histogram by 1000 fakes (7000 entries, 16 per thread) raised the block size to 448; at 143 registers the T4 allows 384 → cudaErrorLaunchOutOfResources. Fix: in morphing modules, 5000 real + 1000 fake entries share the 6000. SimplePixelTopology.h untouched.

Code 2: per module, and loading a strip

PixelClustering.h, inside FindClus

const uint32_t moduleSize = morphingModuleSizes[morphingIndex];             // rows << 16 | cols
const uint32_t nRows = morphing::rows(moduleSize), nCols = morphing::cols(moduleSize);
const uint32_t wordsPerColumn = divide_up_by(nRows, 32);
const uint32_t lastWordMask = (nRows % 32 == 0) ? 0xffffffff : (1u << (nRows % 32)) - 1;
// histogram filled with the real pixels only: hist.off[col] = first pixel of column col
for (uint32_t firstCol = 0; firstCol < nCols; firstCol += morphing::stripCols) {
  const uint32_t nearFirst = (firstCol > 0) ? firstCol - 1 : 0;
  const uint32_t nearLast = std::min(firstCol + morphing::stripCols + 1, nCols);
  if (hist.off[Hist::bin(nearLast)] == hist.off[Hist::bin(nearFirst)])
    continue;                                                 // empty strip: skip
  const int32_t bufferFirstCol = firstCol - morphing::halo;    // buffer starts 2 columns before
  // ... clear image and temp (48 x wordsPerColumn words) ...
  const uint32_t jFirst = hist.off[Hist::bin(loadFirst)], jLast = hist.off[Hist::bin(loadLast)];
  for (uint32_t j : independent_group_elements(acc, jFirst, jLast)) {  // 48 columns, contiguous
    auto pixel = digi_view[hist.content[j] + firstPixel];
    uint32_t index = (pixel.yy() - bufferFirstCol) * wordsPerColumn + pixel.xx() / 32;
    alpaka::atomicOr(acc, &image[index], 1u << (pixel.xx() % 32), alpaka::hierarchy::Threads{});
  }
  // ... dilate, erode (next slides) ...
}
// clear the histogram and fill it again with real + recovered pixels: the rest of FindClus is unchanged

Code 3: dilation, 32 rows per thread

Identical to the Phase-1 bit logic; only the layout is dynamic

for (uint32_t i : independent_group_elements(acc, bufferWords)) {  // word i = 32 rows of one column
  uint32_t col = i / wordsPerColumn, word = i % wordsPerColumn;
  int32_t moduleCol = bufferFirstCol + col;
  if (col == 0 or col == bufferCols - 1 or moduleCol < 0 or moduleCol >= nCols)
    continue;                                            // outer halo column: only read
  uint32_t img = image[i];
  // OR of this column and its two neighbours, shifted by 1 to make room for the previous row
  uint64_t buffer = uint64_t(img | image[i - wordsPerColumn] | image[i + wordsPerColumn]) << 1;
  if (word > 0)                                      // bit 0: last row of the previous word
    buffer |= ((image[i - 1] | ...) >> 31) & 1;
  if (word < wordsPerColumn - 1)                     // bit 33: first row of the next word
    buffer |= uint64_t((image[i + 1] | ...) & 1) << 33;
  uint32_t neighbours = uint32_t(buffer) | uint32_t(buffer >> 1) | uint32_t(buffer >> 2);
  uint32_t fake = neighbours & ~img;     // empty, with at least one of the 8 neighbours set
  if (word == wordsPerColumn - 1)
    fake &= lastWordMask;                                // no rows past the module
  temp[i] = fake;
}

L1 strip: 48 × 21 = 1008 words over 384 threads → about 3 words per thread

Code 4: erosion and the recovered pixels

One popcount + one atomicAdd per 32 rows

for (uint32_t i : independent_group_elements(acc, stripCols * wordsPerColumn)) {  // the 44 strip columns
  uint32_t col = halo + i / wordsPerColumn, word = i % wordsPerColumn;
  uint32_t index = col * wordsPerColumn + word, tmp = temp[index];
  if (bufferFirstCol + col >= nCols or tmp == 0) continue;
  uint32_t value = image[index] | tmp;
  uint32_t above = image[index - wordsPerColumn] | temp[index - wordsPerColumn];   // column - 1
  uint32_t below = image[index + wordsPerColumn] | temp[index + wordsPerColumn];   // column + 1
  if (word == wordsPerColumn - 1) value |= ~lastWordMask;   // beyond the last row: filled
  uint32_t previous = (word > 0) ? (... >> 31) : 1, next = (word < wordsPerColumn - 1) ? (... & 1) : 1;
  uint32_t left = (value << 1) | previous, right = (value >> 1) | (next << 31);
  uint32_t recovered = tmp & left & right & above & below;       // plus erosion, 32 rows at once
  uint32_t first = alpaka::atomicAdd(acc, &fakePixels, alpaka::popcount(acc, recovered), ...);
  for (uint32_t k = first; recovered != 0; ++k) {                // one fake digi per set bit
    uint32_t bit = alpaka::ffs(acc, int32_t(recovered)) - 1;
    recovered &= recovered - 1;
    if (k < maxFakesInModule) {
      auto fake = fakes_view[firstFake + k];
      fake.xx() = word * 32 + bit;  fake.yy() = bufferFirstCol + col;  fake.moduleId() = thisModuleId;
    }
  }
}

Why a new namespace and a new header

Shared by host and device, and by Phase 1 and Phase 2

::pixelClustering::phase2Morphing in SiPixelMorphingConfig.h

  • needed by both the host producer (size check, packSize, default MaxFakesInModule) and the kernel (strip layout)
  • header already included by both; outside the Alpaka backend namespace, so host code can use it
  • next to the existing ::pixelClustering constants (invalidModuleId, …)
  • separate from Phase-1 pixelStatus, whose 160×416 layout stays constexpr and untouched
  • a static_assert keeps the strip buffer within the Phase-1 size

SiPixelMorphingRegions.h, namespace siPixelMorphing

  • parseRegions / skipDetId were private members of the Phase-1 SiPixelRawToCluster
  • Phase 2 needs exactly the same region syntax and selection
  • moved, not copied: one implementation for both producers (91 lines removed from Phase 1)
  • host-only (boost, TrackerTopology): kept out of the device headers
  • Phase-1 behaviour unchanged

Register limit on the T4

Measured limit, inferred reason

  • FindClus, Phase 2, sm_75: 143 registers per thread
  • driver reports maxThreadsPerBlock = 384
  • 65 536 / (32 × 144) would allow 14 warps (448); the lower limit is likely the per-quarter register file (16k per SM sub-partition): inferred, not measured
  • 448 threads → cudaErrorLaunchOutOfResources

How it was measured

  • cuobjdump -res-usage: registers, shared memory
  • cudaFuncGetAttributes: maxThreadsPerBlock
  • compute-sanitizer: 0 errors
  • SerialSync passed in both failing cases
