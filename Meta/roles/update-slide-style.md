# Work-update slide style

Rules the keeper follows for personal work-update decks. Newer rules win.
Each rule cites the dated, verbatim comment from Chirayu it came from (log below).
Consolidated slide instructions (all decks, CMS talks, reviewing, talk feedback log): [[Meta/slides/instructions]].

## Rules
- Make slides for results, reportable work and meaningful status updates. Routine
  handoffs stay in notes; a new note does not automatically need slides (Chirayu,
  2026-11-05, comment below).
- Use only as many slides as the material warrants. The ten-slide full-rerun handoff
  deck was unnecessary; ask when unsure whether there is enough to present (same comment).
- Rendering checks must include the intended viewer. JavaScript-only Markdown can
  appear blank in Obsidian's HTML viewer with scripts disabled. Keep content readable
  without scripts and distinguish browser checks from checks in Obsidian (keeper
  implementation response to the rendering report below; Obsidian itself was not controlled).
- Remaining defaults: status first when relevant; one result per slide with its plot;
  few words; exact tables and sources in backup when needed.
