**The components work, but the implementation does not yet deliver the complete intended workflow.** Sonnet, Hindsight, Arch-Router, embeddings, OMP and T3 are live. The principal gaps are split worker ownership and incomplete hopping/continuation, approval-policy discrepancies, quota/family handling, conductor launch defaults, and a still-active second memory entry point. Conclusions below rest on source inspection, read-only runtime commands, read-only SQLite queries and the existing conductor conversation—not on recalled history. Hindsight recall was used only to orient the investigation; it is not proof of current behavior.

It does not attach to the verified T3 conductor. **[INFERENCE]** Using plain `ai` alongside the existing T3 thread can create another coordinator; no single-conductor ownership lock is present in that path. The live global registration currently supplies the correct cwd, but the checked-in MCP config does not. Some existing off-vault rows may be legitimate user-requested exceptions; the two recent wrong launches are directly acknowledged mistakes.

The installed OMP extension still injects `MEMORY.md` unconditionally when present, without consulting `autoMemoryEnabled`; it matches the repository extension.
