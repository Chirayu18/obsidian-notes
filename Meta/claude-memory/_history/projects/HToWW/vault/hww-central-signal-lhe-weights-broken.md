MEASURED 2026-10-13 (`runall/lhe_xcheck.py`, 2022postEE file vs a DYto2L-2Jets amcatnloFXFX control):
- The control is clean, so the sample is broken, not our reading of it.
- In central H+c, every computed LHE variation is ~2x the nominal: scale 1.83–2.52 with both directions up; PDF replicas (LHA 325500, nf_4) about 2.2 with 0.6% per-event spread.
- Scale [4] and PDF member 0 are exactly 1, i.e. copies of the nominal.
- The offset depends on FxFx multiplicity (LHE_NpNLO 0 vs 1: replicas 2.26 vs 1.80).
- H+b shows the same pattern. The cause is unknown; the "0.5x scale" story is a guess.

Run 2 UL16–18 H+c 4FS/3FS and H+b 5FS (FxFx and plain amcatnlo) are CLEAN with the same check, so this is a Run 3 production problem (confirmed broken in 22EE and 23).

ROOT CAUSE (2026-10-13): the custom running-charm-Yukawa `_mg5amc.patch` (ymc = 0.986 at 3 GeV) does not reach the MG 2.9.9 variation weights, so they lack (m_c(mu)/m_c(3 GeV))^2 ≈ 0.44 per event. The NOMINAL is OK: sigma 0.298 pb (Run 3) vs 0.264 pb (Run 2 at 13 TeV). Per-event fix: r = mean(PDF replicas)/member0, scale_w / r (x (m_c(k mu0)/m_c(mu0))^2 for muR). muF-only validated against Run 2 to <1% (`runall/percorr_test.py`).

TRUE ROOT CAUSE (2026-10-13, later): the WW sample used OUR OWN el8 gridpack (MG 2.9.18, built from /eos/home-c/cgupta/HToWW/mcm_grid/genproductions_scripts). Its runcmsgrid.sh runs the python `systematics` module (reweight_scale/PDF=False, store_rwgt_info=True), which lacks the running-Yukawa factor. The clean gamma-gamma FxFx gridpack (MG 2.9.9, bevila_t) skips systematics via a sample-specific runcmsgrid change. So the gamma-gamma 4FS FxFx sample is the CLEAN reference. The per-event fix is exact for muF only; muR is off 1–4% because the factor is missing per contribution. MiniAOD has no rwgt comments, so no exact recomputation is possible.

LATER 2026-10-13 (`runall/unmix.py`): the apparent NpNLO=1 H-event residual vs γγ (1.83 vs 2.33 for μR0.5) is mostly the γγ REFERENCE.
- γγ has 1.7% of those events (7% of the weight) with constant ratios 6.198 / 0.308; WW has none.
- The merging scale spectrum also differs.
- Per scale bin the medians agree to 0.3%.
- A two-piece unmixing (real at n+1 scale, counterterms at n-body scale, rebuilt from LHEPart) moves the fix by only 1%. The per-event fix is good to ~1%.
- Don't use γγ class means as truth.

CORRECTED same day: the Run 2 UL18 WW sample (MG 2.6.5, clean) has the same spike and low-scale events as γγ (MG 2.9.9). So OUR WW sample (MG 2.9.18) is the outlier: it lacks the spike weights and the NpNLO=1 events with jet kT < 30 GeV, which is a nominal-level difference.
- The cards and the Pythia FxFx settings (qCut 30 / qCutME 10) are identical across the three samples.
- The per-event fix is fine for the events present. The open issue is the MG version / generation itself.

SPIKE = MG's 1 GeV renormalisation-scale floor. Our raw weights carry them as 0.968 / 0.239.
- The tables now start at 1 GeV, so floor events come out exactly 6.1986 / 0.3078.
- Events with F above F(1 GeV) now get no variation.
- Edge-case audit (`runall/edge_audit.py`) is clean.

EVENT-MIX ROOT CAUSE (2026-10-13): our Pythia fragment LACKS `JetMatching:jetAlgorithm=2`, `etaJetMax=999.` and `coneRadius=1.`.
- FxFx code forces kT, so only etaJetMax and coneRadius matter. Their defaults are 2.5 and 0.7, so the veto ignores |η| > 2.5.
- These lines are NOT meant to be dropped: current DY and ggH FxFx fragments in the same release have them.
- All 7 H+c/H+b WW GEN requests lack them. GEN ticket draft is in the vault.
- The user followed the official instructions, so the cause is the master-workflow default plus the request fragment.
- Forward 1-jet events are 7× rarer and forward hard 0-jet events 10× more common than in the clean samples.
- This can't be fixed by reweighting; it needs re-production with the gridpack fix AND the fragment fix.

**Why:** the 2026-10-02 fix (`lhe_norm.py`) divides by the global generator mean. That is exact for PDF, because `lhepdf.py` centres on the per-event replica mean. For scale it leaves a fake shape: H+c (2,2) is 1.06 / 0.77 for NpNLO 0 / 1, with both directions down, whereas the DY control varies about ±4% in opposite directions.

IMPLEMENTED 2026-10-13: `analysis/corrections/lhe_yukawa_fix.py` + tables `analysis/data/lhe_yukawa/` (generated by `tab.f`, the patch's own runalpha/runmass compiled from MG v2.9.10; alpha_s(MZ) from LHAPDF: 0.11266 nf4 / 0.11800). Wired via `lhescale.py` `yukawa_table`. The gridpack-level reason the factor drops is still unproven.
